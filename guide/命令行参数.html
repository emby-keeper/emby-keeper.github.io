命令行参数 ​

建议使用网页管理

面板模式不需要记忆命令行参数: 运行 embykeeper web 后, 在浏览器中完成 Telegram 登录、账号添加和任务配置即可. 详见 🖥️ 面板模式部署.

网页管理 ​

bash
embykeeper web

面板默认监听 0.0.0.0:8000, 需要先设置环境变量 EK_WEBPASS 作为登录密码. 启动时面板会自动在 127.0.0.1:8001 拉起业务后端 (即 embykeeper --api), 一般无需手动启动.

常用选项:

参数默认值说明
--host0.0.0.0面板监听地址
--port8000面板监听端口
--target-host127.0.0.1业务后端地址
--target-port8001业务后端端口
--autostart / --no-autostart自动启动是否随面板拉起业务后端
--debug / --no-debug关闭是否输出访问日志
--cors(无)额外允许的跨域来源, 可重复指定

子命令 serve 与 dev 分别用于前台运行和开发调试, 详见 embykeeper web --help.

设置环境变量 EK_MONGODB 后, 面板与业务后端的配置、缓存、面板设置都保存在 MongoDB, 容器无需挂载数据目录:

bash
EK_WEBPASS=你的密码 EK_MONGODB='mongodb://用户名:密码@主机:27017/embykeeper' embykeeper web

数据库模式的行为与迁移方式见 面板模式部署 - 用 MongoDB 无持久化部署.

参数说明 ​

配置文件 ​

  • 第一个位置参数是配置文件路径, 例如 embykeeper config.toml.
  • 置空时会自动生成模板 config.toml; 也可以使用环境变量 EK_CONFIG_FILE 指定.
  • 使用面板模式时, 配置文件由面板在数据目录中生成和维护, 无需手动指定.

模块开关 ​

  • 不添加任何模块开关时, 开启全部功能.

  • 添加开关时, 仅开启对应的功能, 例如 embykeeper -c -s 只运行 Telegram 签到和自动水群.

  • 账号层面还需要在配置文件中启用对应功能 (monitor / messager / registrar 等), 详见 🔧 配置文件.

    bash
    # 启动所有功能
embykeeper config.toml

# 仅启动每日签到
embykeeper config.toml -c

# 仅启动每日签到和水群
embykeeper config.toml -c -s

  • 签到时间区间、保活间隔天数现在只在配置文件或面板中设置, 命令行不再接受时间参数. 对应配置项为 checkiner.time_range 与 emby.interval, 详见 🔧 配置文件.

  • --registrar-bot / -R 用于快速反复尝试注册指定机器人 (Embyboss), 例如:

    bash
    embykeeper config.toml -R XiguaEmbyBot

  • --api / -a 启动业务后端 API 服务器, 供面板调用 (--api-host / --api-port 指定地址与端口). 使用面板模式时由面板自动启动, 通常不需要手动运行.

运行方式 ​

  • --instant / -i 在启动时立刻执行一次任务, 之后进入计划执行.
  • --no-instant / -I 为默认行为, 启动后按计划等待, 不在启动时立即执行. 调试签到时可以用它避免反复触发.
  • --once / -o 只执行一次任务后退出; 默认的 --cron / -O 会进入长期计划执行模式.
  • --noexit / -N 让长期任务在没有可用账号时继续监控等待, 而不是直接退出.

日志与调试 ​

  • --debug / -d 开启调试日志, 重复使用 (-dd) 会输出更详细的内容.

  • --simple-log / -L 简化日志格式, --disable-color / -C 去掉 ANSI 颜色码, 适合输出到不支持颜色的平台.

  • --top / -T 在终端底部显示 CPU / 内存占用与实时状态, 默认关闭.

  • 部分参数可以通过环境变量设置, 优先级低于命令行:

    参数环境变量
    配置文件EK_CONFIG_FILE
    MongoDB 存储EK_MONGODB
    --instantEK_INSTANT
    --debugEK_DEBUG
    --debug-cronEK_DEBUG_CRON

Docker 部署使用命令行参数 ​

当通过 Docker 部署时, 末尾的所有参数将被传递给 Embykeeper, 例如:

bash
docker run -v $(pwd)/embykeeper:/app --rm -it --net=host embykeeper/embykeeper -e

当通过 Docker Compose 部署时, 您需要通过修改 docker-compose.yml 中的 command 项, 从而调整命令行参数, 例如:

yaml
version: '3'
services:
  embykeeper:
    container_name: embykeeper
    image: embykeeper/embykeeper
    command: '-e'
    restart: unless-stopped
    volumes:
      - ./embykeeper:/app
    network_mode: host
